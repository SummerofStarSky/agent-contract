# code · 代码与工程改动

## 骨架

1. **改动清单** — 文件 + 做了什么，一行一个。
2. **关键 diff 摘要** — 只贴关键行，不整段粘。
3. **验证方式** — 命令 + 预期输出。
4. **回滚点** — 怎么撤回这次改动。
5. **自检** — 表格（见 core §5）。

## 硬约束

- 改动前先说明要碰哪些文件；不静默修改。
- 不引入新依赖，除非我明确同意。
- 报错信息原样保留，不改写、不省略。
- 未能实际跑通时，写「未验证」并说明卡在哪一步。
- 一次改动只解决一个问题；顺手改的东西单独列出来。

## 例外

- 我说「直接改」→ 跳过第 1 步说明，但仍要给验证方式。
